# CfromP 缓存返值透明性的静态边界

本次是夜间续跑中的有界静态复核。只读取当前Shipping EXE，SHA256为`ccd1db79c2eb3668242c4c10d271234963bc9dc1efa3ec0afddace444d1afcab`，没有执行原缓存、加载游戏模块或修改冻结的R3、A、B、C资料。

结论：**在缓存容器保持有效、其条目只由已审查的函数维护、浮点环境稳定的前提下，所见控制流支持缓存对CfromP返回值透明。** 命中返回此前保存的同一输入的计算结果，未命中计算并保存该结果。这是一条带前提的静态不变量，不是完整TLS/分配器/wrapper的动态等价证明。

## 本轮三条线索

1. 重新读取CfromP完整范围`0x1445ac2e0..0x1445ac784`，确认输入规范化、命中读取、未命中结果与调用参数。
2. 追入以前没有展开的配对插入函数`0x1445a49c0..0x1445a4bff`，检查存入键和值的实际字节及重复键分支。
3. 检查删除函数`0x141156d10..0x141156dbf`、重建桶链函数`0x1445b0fd0..0x1445b1169`和队列扩容窗口`0x141144f30..0x141144ff0`，核实哪些字段会改变、哪些外部调用仍留在证明边界外。

前两份`.pdata`入口片段曾只覆盖删除/扩容函数的前33/47字节。本轮沿明显的向前分支补至返回/失败尾端，最终`current-pe-ranges.json`明确记录所用连续范围；额外`*-window`文件只是调查窗口，可能含相邻函数，不作为整个函数的声明范围。

## 可使用的条件性返值不变量

令`p=min(P,1)`，域为有限`P>5e−5`；令`F(p,E)`是在浮点环境`E`中执行原CfromP数学块得到的结果。

假设：

- 初始缓存为空或所有有效条目满足`Map[p]=F(p,E)`。
- 所见插入/删除/桶链辅助函数维持有效容器，不发生内存损坏、分配失败、外部并发或重入修改。
- 同一缓存条目生存期内浮点舍入/异常控制环境稳定，输入到原数学块的运算环境没有改变。

那么：

```text
hit(p):  返回 Map[p]，即 F(p,E)
miss(p): c = F(p,E)
         必要时淘汰一个旧key
         存储精确(Pbits,Cbits)配对
         返回局部c
```

删除使部分键不存在，重建桶链改变查找路径；在上述容器不变量下，它们只会导致后续重新计算，不会改变计算结果。原有同哈希不同P的链比较避免把哈希碰撞直接当命中。

**这条结论仅覆盖函数返回数值。** 分配次数、TLS状态、执行时长、失败路径和整局随机状态不属于“透明”的承诺。

## 不能删除的剩余边界

1. 原TLS结构、分配/回收、桶扩容、重复key和第129次淘汰未在原wrapper中动态执行验证。静态数据流不能替代这些证明。
2. 键只有规范化P，没有记录MXCSR/浮点舍入模式。若缓存生存期内环境变化，旧值可能对应旧环境，不能无条件声称它等于当前环境重新计算的结果。本轮没有发现游戏改变相关环境的证据，也没有证明整个程序绝不改变。
3. 外部内存破坏、动态重入/容器异常可能破坏不变量。本轮没有发现具体缓存错误，也没有穷尽证明其不会发生。
4. 无直接随机调用不等于完整传递调用图或整会话随机交错已证明。R3已有随机状态边界保持不变。

因此无需将“原缓存wrapper未执行”解释为“CfromP数学规则尚不明确”；数学本身已有独立原生向量证据。也不能据此把剩余wrapper缺口改成已完成。

# 当前安装包的原生弹射、引力与回放机制

基准：Steam App 3910830，Build 25684533。Shipping EXE SHA256 为 `ccd1db79c2eb3668242c4c10d271234963bc9dc1efa3ec0afddace444d1afcab`，ImageBase `0x140000000`。本次只读当前EXE和重新解包的Kismet字节码，没有启动游戏或执行原生游戏代码。

本专项保存48个游戏模块反射函数的签名、Exec VA、代码范围、机器码SHA256和原始Blueprint调用位置。47个Exec边界来自`.pdata`；`StopFollowing`是没有`.pdata`的叶子跳板，其范围截到当前机器码的无条件尾跳转，另记录被跳转的实现体。全部48段边界内字节均被解码。

`native-functions.json`的48条中，17个有直接Blueprint调用，共32个调用点；其余条目标为“未找到Blueprint直接调用”，**不据此标为废弃**。其中还包括表格编辑辅助、技能审计工具与日志管理，函数名字不能代替逐分支语义还原。

旧分析稿的384个原生地址已逐条从当前EXE重新读取和解码，381个已存在于新的深度反汇编；剩余3个另存当前函数体。15项默认值直接解码指令立即数并与引用值比较一致。47行复杂常量说明保留当前指令证据；地址相符不代表所有引擎语义已证明。

## 1. 数据与调用边界

弹射计算涉及两个层次：

- 原生路径库：负责逐步扫掠、引力转向、接触恢复、物品扫描、预览链、路径跟随和潜伏动作。
- Blueprint：提供实时角色宽度/高度/疲劳预算/弹射距离，决定主段与终段、反弹触发次序、装备响应及运动曲线。

当前Demo的常见路径是`BuildLegacyPreviewMain/Terminal`，每个原生路径的`MaxBounces`为0，然后由Blueprint和预览圈组成多段反弹链。不能把原生通用`BuildTrajectory`的一次内部多反弹直接当成Demo实际整次发射流程。

可查来源：新解包目录中`blueprints-pseudo/CatapultHero/BP/交互/碰撞预览圈.txt`、`BP/Skill/效果/蓝图_效果_可控弹射.txt`、`BP/Skill/效果/蓝图_效果_可控反弹时交互.txt`，以及`native/deep/LaunchTrajectoryLibrary.*.asm`。

## 2. 参数与基础输入

| 原生参数 | 默认值 | 实际限制 |
|---|---:|---|
| DistancePerLeg | 1000 | 必须有限且大于0 |
| MaxBounces | 0 | 钳制到0–32 |
| StepDistance | 20 | 钳制到1–200 |
| MaxPoints | 2048 | 钳制到2–4096 |
| ProbeRadius | 80 | 至少1 |
| ProbeHalfHeight | 80 | 胶囊半高至少为半径 |
| bUseSphereProbe | false | Legacy主路径设置为球 |
| CollisionChannel | 3 | Visibility |
| MaxTurnDegreesPerStep | 15° | 钳制到0–90° |

这些是构造/参数默认值，不应覆盖Blueprint显式传值。直接指令证据见`verified-defaults.json`。

角色输入已经从原始表和Kismet赋值链补齐，见`hero-launch-inputs.json`。例如幽冥骑士基础宽度56、高度56、最大疲劳4、弹射距离500；主预览半径读取实时宽度×0.95，基础对应53.2；终段读取实时宽度。动态状态与装备可改变读取结果，因此数据表基础值不是永久运行常量。

`BP_ManeActor`初始化把配置的高度、宽度、最大疲劳赋给角色，并调用`SetCapsuleHalfHeight`和`SetCapsuleRadius`。这关闭了旧稿U-12中“参数来源未查”的缺口。

## 3. 路径构建的执行顺序

`BuildPathCore`实现入口为`0x1445a9900`。主要顺序如下，完整旧分析逐地址说明保存在`historical-native-draft.md`第5节；其未知项以本次`native-gaps.json`复核结论为准。

```text
初始化输出：InvalidInput、空路径、距离0、反弹0
取得World，方向作2D安全归一化；检查起点/距离有限性
钳制参数，建立碰撞查询及忽略对象集合
加入首点，Remaining = 每段距离
循环：
    Remaining不足 -> DistanceExhausted
    步长 = float32(min(Remaining, StepDistance))
    应用引力转向
    对当前位置到步末做主扫掠
    若段首贴面/穿透 -> 按限定偏移尝试脱离；失败则Stuck
    扫描物品，排序、去重、记录距离
    若遇需要预览拾取的引力源 -> 移除其后续引力，可能截短此步
    加入路径点，更新float32总距离/剩余距离
    若发生阻挡 -> 检查反弹预算/法线/目标条件
        不允许 -> Collision
        连续过短碰撞 -> Stuck
        否则反射，反弹数加1，重置下一段距离，再添加分离偏移
    达到点数上限且尚无停止原因 -> PointLimit
```

停止原因原枚举：InvalidInput=0，DistanceExhausted=1，Collision=2，Stuck=3，PointLimit=4。已设置的非零停止原因不再覆盖；当同一步既用完距离又填满点数，点数检查先于下一次距离检查。

位置、方向、引力向量累计使用double；Remaining、TotalDistance、步长、推进量等中间值保留float32舍入。复现时不能全部改为任意精度数值或全部double后宣称逐位一致。

## 4. 引力、反射与接触恢复

`SteerByGravity`入口`0x1445a7d90`。每个引力源需Strength和Radius有限且大于0，且`1e-8 < 距离 < Radius`。

```text
t = 1 - distance / Radius
w = sign * Strength * t² * (3 - 2t)   # Mode=0吸引，其余值排斥
a += normalized2D(sourcePos - pos) * w
k = float32(stepLength * 0.01)
desired = normalized2D(direction + a*k)
delta = wrap(angle(desired)-angle(direction), -180°, 180°)
delta = clamp(delta, -MaxTurn, MaxTurn)
newDirection = normalized2D(rotateZ(direction, delta))
```

原生普通反射使用`normalize2D(D - 2(D·N)N)`。段首恢复不是简单“向外挪一点”：尝试偏移顺序为`0.5,1,2,4,6,8,12,16,24,32,48,64,96`再到`min(MaxExit,Remaining)`，每个候选还需满足剩余距离、限定半径以及忽略出发组件后的扫掠/重叠检查。

球/胶囊/盒组件的`MaxExit=clamp(1.5R,12,96)`；其他组件为`min(0.25R,12)`。穿透深度限制为`min(0.1R,4)`。当前库代码能恢复这些阈值，Chaos真正怎样报告“刚好相触”、角落最小脱离方向和膨胀量，仍是U-04未闭合项。

## 5. 物品扫描与预览链

物品扫掠使用通道19，按Hit.Time升序排序；同一对象在整个构建过程中去重。记入物品命中的距离为：

先算`d=float32(clamp(Time,0,1) * Advanced)`，再算`float32(float32(d + Total) + 2)`。

排序实现是不稳定的introsort，等Time项不能随意替换成稳定排序。输入命中数组本身又来自引擎扫掠，因此等时次序没有因恢复排序调用地址就自动解决。

引力拾取点会从本次后续引力源集合移除，并可能截短当前步。这与普通碰墙反弹不是同一分支；预览圈还维护PendingGravityBounces和OrdinaryBounceCount。

旧稿U-11已缩小：常规玩家被动创建加速点时，BeginDeferred/FinishSpawning使用的Transform明确为Scale(1,1,1)；激活范围组件的序列化SphereRadius是50，引力组件Radius是500、Strength是1.4。`尺寸=160`没有在该类方法中作为球半径/缩放赋值，不能把160直接当半径。组件未序列化相对缩放的原生默认及其他动态创建路径仍保留验证边界。证据见`pickup-scale-evidence.json`。

## 6. Blueprint反弹条件与角度

旧稿U-14的两个函数已经在本次原始Kismet中定位，完整函数存为两个`*-source.json`。

`判断目标可反弹`：目标实现GameplayTag接口且拥有以下任一标签，**或者目标类恰好等于`蓝图_动态网格_C`**，返回true：

- 环境.房间.有弹性
- 可交互.角色.AI.仇恨
- 可交互.角色.玩家
- 可交互.角色.AI.物品

`计算反弹角度`：通过源`CalculateDirection`读取入射和法线角。普通分支输出角度`2×法线角－入射角`的ForwardVector；保持方向分支输出入射旋转体，同时方向向量为入射向量绕Z旋转180°。应保留源调用的向量朝向和该分支语义，不能用一句通用反射公式替换所有分支。

## 7. 路径回放与潜伏等待

Follower accepted start会增加Serial，清零Elapsed/TravelledDistance/CurrentIndex并打开tick。带曲线时：

```text
Duration = max(TotalDistance / Speed, 0.01)
Elapsed = min(Elapsed + dt, Duration)
t = Elapsed / Duration
targetDistance = TotalDistance if t>=1 else clamp(curve(t),0,1)*TotalDistance
Advance = max(targetDistance - TravelledDistance, 0)
```

不带曲线时按`float32(dt*Speed)`推进。跨越完整路径点时会触发碰撞回调，碰撞后结束本次tick，剩余推进量不会自动带入下一次。每次移动和广播后要复查对象有效性、Serial与Following状态。

Legacy Bridge使用不扫掠的TeleportPhysics移动到已计算路径点；通用Native模式另做实际移动扫掠并检查非预期碰撞。两者不能混为同一种移动语义。

Blueprint主段速度为`min(疲劳×300+2000,6000)`，使用`可控反弹曲线`；终段速度为`移动当前速度×0.3`，使用`可控终末确定曲线`。两条曲线的原始键、切线、权重与权重模式见`playback-curve-keys.json`，不能换成近似的统一缓动曲线。

主段达到末端后：先更新运动数据，再发出可控反弹时机，效果读取刚完成的当前圈命中并触发交互，之后才推进PlaybackIndex/疲劳。潜伏动作依赖Follower的Serial和State，结束后才恢复Blueprint Linkage。**同帧还是下一帧恢复取决于引擎tick/latent调度，U-10仍未完全恢复。**

旧稿U-13已定位：`结束移动判断`遍历有效效果，筛选“效果.时机.结束移动后”，写入触发时机，再调用该效果`持续中触发`。该函数本身没有直接修改移动当前速度；后续具体效果的作用仍按运行状态决定。

## 8. 不能从本次结果推出的结论

- 48个函数有代码哈希不等于48个函数全部语义、所有条件分支均已还原。
- 旧原生稿中的理想几何测试向量是算法推导样例，不是原游戏引擎的运行oracle。
- Chaos边缘接触、等时命中次序、Actor迭代次序、tick与latent相对调度仍可能影响逐位/逐帧一致性。
- Native/DataTable工具没有直接Blueprint调用不等于它们未使用；动态/native调用路径需要另证。
- 人工命名的函数/虚表槽仍标为推断；当前地址和字节已经核对，但符号名字并非恢复出的调试符号。

这些限制逐项保存在`native-gaps.json`，不得在总交付中被“全部包已读出”掩盖。

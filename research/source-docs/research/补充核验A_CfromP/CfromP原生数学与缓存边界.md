# CfromP 原生数学路径补充验证

这是R3封存之后的新证据，未改R3表格、文档或原游戏文件。全部工作位于 `algorithms/native-followup/`。

## 新增验证

从当前安装EXE复制两个原始数学基本块：

- `0x1445ac449 .. 0x1445ac4e1`
- `0x1445ac52f .. 0x1445ac5df`

这两个范围覆盖原生CfromP的目标夹紧、概率期望计算、80轮二分和5e−5退出容差。原缓存命中返回块没有复制，间隙填入INT3；所有数学指令除RIP常量重定位外保持原字节。`copy-audit.json`逐条记录比较，断言没有其他字节修改。

调用入口由独立ABI适配代码保存非易失寄存器，使用本机UCRT `_finite` 及按原比较方式重建的检查处理非法输入，然后进入原数学块。**有限性和阈值的前置保护由重建shim执行，原wrapper前置路径仅作静态核对；不能称为已动态执行原保护wrapper。** 输出在原数学块进入缓存写入之前截取。这里只加载UCRT，不加载原游戏模块，没有启动游戏，也没有接触游戏世界函数。

**1052次harness结果与独立Python参考逐位一致，零差异，其中1044次实际执行复制的原数学块，8次只执行重建的ABI保护分支。** 具体统计：1028个单独案例中1020个进入原数学块，8个直接返回；另有24次重复输入执行原数学块。该数字与R3的1017组批量/量化/均匀抽样测试完全分开。

8个shim-only案例为：负Infinity、−1、负零、0、阈值前一个浮点、阈值5e−5、正Infinity及NaN。它们提供harness与独立参考的一致性检查，并不增加原数学块或原guard wrapper的动态覆盖。

新增输入包含：

- 0.001到1.000的千分位网格。
- 0、负数、负零、±Infinity、NaN。
- 阈值5e−5前一个浮点、阈值自身、后一个浮点。
- 1前后相邻浮点、2及1e308，实际执行复制的`minsd`指令（原VA `0x1445ac452`），验证夹紧到1的数学行为。
- 四组经原哈希公式构造的不同P碰撞对，按P/Q/P/Q/Q/P顺序重复计算，共24次。

保存的是每个输入、输出的IEEE754 double小端位模式，比较使用位相等，不使用近似容差。

例子：

| 输入P | 原数学路径返回C |
|---|---:|
| 0.1 | 0.01474609375 |
| 0.2 | 0.055712890625 |
| 0.5 | 0.3021240234375 |
| 1 | 0.999969482421875 |

P=1对应的C不是必须恰好1，原函数允许误差5e−5；这里保留实际退出结果。

## 缓存静态结构的新增明确定位

完整原函数在 `0x1445ac2e0 .. 0x1445ac784`。其数学部分已执行，但缓存外壳仍只完成静态还原。

| 字段/操作 | 指令证据 | 解释与边界 |
|---|---|---|
| TLS基址 | `0x1445ac326`读GS:[0x58]，`0x1445ac32f`读TLS索引，`0x1445ac34d`取线程槽 | 不可把未初始化的本进程TLS当原游戏TLS执行 |
| 初始化标志 | TLS+0xf10，位1和2；`0x1445ac36a..3ae` | 初始化路径注册两类清理回调；没有调用这些游戏缓存对象 |
| Key→C映射 | TLS+0xeb0；`0x1445ac3bc..402` | 当前容器数据地址、桶数组和链指针由引擎容器维护 |
| Key哈希 | `0x1445ac3c5..3d6` | `uint32(high32(Pbits)*23 + low32(Pbits))` |
| 桶选择 | `0x1445ac3df..3fd` | 哈希与桶数−1按位与；原容器保证的桶容量条件未在本oracle重建 |
| 碰撞比较 | `0x1445ac410..42b` | 沿24字节条目链访问，以`ucomisd`比较完整double值，不仅比较哈希 |
| 命中返回 | `0x1445ac4e1..52e` | 返回条目+8的C，直接返回，没有更新后述插入队列 |
| 插入历史 | TLS+0xf00；`0x1445ac5df..5f8` | 数量达到0x80即128时进入移除旧key分支 |
| 队列游标 | TLS+0xf14；`0x1445ac619..6fd` | 替换游标处key，游标加1再取模128 |
| 删除链节点 | `0x1445ac63e..6c6` | 查旧key并更新链后调用`0x141156d10`容器删除辅助函数 |
| 动态数组增长 | `0x1445ac70b..721` | 容量不足调用`0x141144f30` |
| 新映射插入 | `0x1445ac73b..768` | 调用`0x1445a49c0` |

从命中直接返回、只在新插入时更新环形历史可得：这是一套按插入顺序淘汰的128项缓存路径，**不能称为“命中后刷新顺序的LRU”**。此结论是静态控制流结论；实际容器分配、哈希碰撞链维护和第129次插入的动态执行仍未被此次oracle验证。

原函数的静态控制流显示，输入在查缓存之前已做finite、阈值与P≤1处理，因此大于1的有限P会使用夹紧后1的缓存键。NaN和低于/等于阈值的值提前返回，不应进入缓存。此次只实际执行数学块内的`minsd`夹紧；原wrapper的finite/阈值提前返回路径未动态执行。

## 为什么没有直接运行整个缓存wrapper

整个wrapper访问本游戏的编译TLS索引、UE动态数组、哈希/稀疏容器以及分配/清理函数。直接把这段代码复制到当前Python线程执行，会错误使用当前进程TLS。为保留可审计边界，此次只执行没有这些依赖的数学路径；没有通过替换游戏世界函数或虚构缓存内存来冒称完整wrapper一致。

四组碰撞输入确实按原哈希公式具有相同keyHash，原数学输出分别与独立参考相符。但这些调用**未经过原缓存**，所以不作为原生缓存命中、碰撞解决、FIFO淘汰的动态证明。

## 调试证据保留

`smoke-01`至`smoke-05`得到不可信的全零结果，原因是反汇编库将一个66前缀`movdqa [RIP+disp32]`错误报告为disp_size=2，重定位替换造成私有缓冲区膨胀。该问题已通过逐条原字节长度核对定位，之后强制RIP位移替换4字节并断言缓冲区长度不变。

`smoke-06`与`native-math-final-01/02`为修复后结果。最终有效证据只使用 `native-math-final-02`，并移除诊断用NOP跳板；旧失败输出仅为工具调试记录，不能引用为Demo结果。

冻结的 `native-math-final-02/vectors.json` 原元数据字段`mathCalls=1052`命名过宽，它实际统计所有harness调用。为保留原始向量文件，未修改其字节；正确分类为1044次原数学执行、8次shim-only保护分支，见 `comparison.json` 和补充工作表的执行类别列。

## 复现

```powershell
python -I cfromp_math_oracle.py --out <一个新的输出目录>
python -I verify_cfromp.py
```

脚本锁定当前EXE哈希，不匹配则停止。`verify_cfromp.py`默认比较本目录的 `native-math-final-02/vectors.json` 和R3独立Python参考，R3文件只读导入且禁用字节码缓存写入。

此补充关闭了“CfromP数学路径仅静态推导、没有原生执行向量”的有限缺口。原生TLS/cache完整wrapper、整会话随机调用交错以及所有浮点输入域的形式化等价仍未关闭。

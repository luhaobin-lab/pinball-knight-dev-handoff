# 原版成长、天赋与怪物经验机制

本卷以本轮重新读取当前安装包得到的静态解包为来源。数据来自 `../provenance/extraction/dump`，不是游戏游玩观察，也不是现有 TypeScript 移植的运行结果。源函数完整字节码、可读反编译片段、文件哈希保存在 `evidence/`。

`growth-tables.json` 包含13张可合并工作表。所有物理天赋表、过期行、忽略行和怪物行均保留。是否出现在普通 Demo 流程中单独标注；“包内存在”不等于“已证实能获得”。

## 1. 三种成长入口必须分开

原包同时存在英雄经验升级、随机多选一天赋、潜能网格分配。不能把它们合并成一个自行设计的“技能点解锁后花金币升级”的统一系统。

| 入口 | 实际数据/代码 | 本卷覆盖 |
|---|---|---|
| 英雄等级 | 游戏模式 `增加经验`、`尝试提升等级`，源等级上限60 | 1–60级经验阈值、累计经验、升级点、锁格移除条件 |
| 天赋多选一 | `UI_主界面.筛选天赋`、`UI_天赋选项`、`BP_ManeActor.添加天赋` | 六张物理天赋表252行、全部951个有限等级、3个无限上限公式、四参数和前置/排斥 |
| 潜能网格 | `UI_潜能页`、`UI_潜能格`、`UI_潜能页_幽冥骑士` | 20个界面实例、132个逐点分配状态、预算与前置条件；普通入口可达性仍需完整引用图闭合 |

## 2. 天赋数值如何随等级变化

源函数为 `函数库_技能.获取技能参数`，伪代码文件第670–698行。完整字节码位于同名 Blueprint JSON 的函数记录。

```text
输入：参数 p，技能当前等级 L，品质 Q，上一次等级 P，差值开关 D
如果 p.品质倍率：
    标量 = p.初始值 + p.提升值 × Q
否则如果 D 且 P > 1：
    标量 = p.提升值 × (L − P)
否则：
    标量 = p.初始值 + p.提升值 × L

输出：整数标记、乘算标记、标量、处理后的词条名
词条前缀 X（区分大小写）或 Y/y 被剥掉；小写 x 保留。
```

该函数没有直接把返回标量乘以角色属性。能力或效果消费方会决定：读取自身、角色、装备、原始值或当前值，是否乘属性，何时取整，以及持续到何时。因此本卷逐级表把“参数标量”和“动态属性依赖”明确分列，不把标量冒充最终伤害。

一个容易误抄的细节：上一级差值条件是 `上一次等级 > 1`，所以从1升2时即使请求差值，返回的仍是完整参数；从2升3时才走差值。这是源分支，不能为了直觉而改写成普遍的相邻等级差。

这252行的参数没有非空 `初始区间`，也没有本轮发现的 `品质倍率=true` 参数。表中仍保留这些原字段，避免把通用参数机制误删。三条 `天赋上限=-1` 是含“忽略”类型的分隔行，使用符号公式保留其无限含义；没有人为塞入一个有限最大等级。

## 3. 天赋获得、费用与前置关系

普通升级效果 `蓝图_效果_升级获取天赋` 在其完成分支调用：三选一、免费、额外等级0。免费选择不扣金币。`UI_天赋选项.更新描述` 计算价格：

```text
价格 = 免费 ? 0 : 本次提升等级 × 3
```

点击分支检查价格不大于当前金币，之后扣除实际价格并调用真实 `添加天赋`。表里的“付费逐级累计”是**假设每次只提升1级、且每次都处于付费入口**的计算值，不代表每个节点固定必须花这笔金币，也不替代普通免费升级。

选项可能一次提升多级。`UI_天赋选项` 的激活分支调用 `递减强化属性(2,0.12,本次提升等级)`，然后加入口给定的额外等级，并按剩余可升等级裁切。无限上限行走另一分支。本卷保留调用位置，不把随机多级当作固定每次+1；该随机算法及序列由随机机制卷详述。

`UI_主界面.筛选天赋` 不是仅按名字抽签。它先清池并逐行读取组合技能表，检查：

- 类型没有“忽略”。
- 目标标签满足任一/全部语义，或目标标签为空。
- 不匹配排除标签、非本英雄标签和已存排除天赋池。
- 英雄等级在配置范围内；已获取天赋数达到前置点数。
- 技能的排斥标签不在玩家已累计的天赋标签容器中。
- 已有同名被动时，当前等级低于上限，或上限为−1。
- 首次获得时，逐一检查前置标签的计数需求。

通过者 AddUnique 后执行 Array_Shuffle。已有同名天赋和首次获得走不同分支；不能把前置条件统一套在所有升级情境上。

添加天赋时：从排斥技能列表里移除自身名，把其他排斥名加入全局排除池；已获取天赋数增加本次等级数；已有实例记录旧等级、增加新等级并重新初始化/执行；新实例挂到角色并执行。类型标签的计数也随本次等级增量累加。

## 4. 潜能网格逐点规则

潜能页当前可用总点数来自 `英雄等级 − 1`，不是本卷另行设计的金币价格。20个节点实例的表引用由 `UI_潜能格` CDO 默认 DataTable 与实例 RowName 合并得到，全部成功找到源行。

`UI_潜能格.判断解锁`：

```text
已解锁 = 未在排除天赋池 且 页已投入点数 >= 本节点前置点数
若“解锁材料”映射非空：
    只取 Map_Keys/Map_Values 枚举的第一项
    已解锁 &= 存档潜能点配置[该键] >= 该值
```

这里字段名叫“解锁材料”，但这一消费方把它解释成**前置潜能名与等级**，没有按名称扣除材料。源映射枚举顺序属于引擎 TMap 语义；多项情况下不能擅自改成“全部前置均满足”。

加减点分支检查新节点点数在 `[0,等级上限]`、新总投入不超过已解锁点数、节点已解锁。减点还检查后继依赖和最深层所需点数。特别记录一个源行为：`修改点数` 中调用角色 `添加天赋` 时传入的等级增量字面值是1，即使该事件请求减点；存档潜能配置和页投入则按事件增量更新。本卷保留实际代码，不修正原版逻辑。普通 Demo 是否能走到所有这些加减点路径仍列为可达性缺口。

## 5. 英雄经验与每级阈值

源游戏模式的 `英雄等级上限=60` 是直接序列化的默认。初始化阈值150；成功升级后：

```text
x = float32(英雄等级 / 60)
q = 曲线表.经验值所需曲线(x)  // 原始关键帧另表完整保存
下一级所需经验 = GridSnap(q × 60 × 75, 5) + 150
```

`增加经验` 先读全局“经验修正%”：

```text
实际增量 = 传入经验 × (1 + 全局经验修正)
如果实际增量 <= 0：不增加
显示提示使用截断整数(实际增量)
当前经验 += 实际增量  // 实际累计没有在这里截断
当 当前经验 >= 当前阈值 且 等级 < 60：
    当前经验 -= 当前阈值
    等级 += 1
    升级点 += 1
    更新新阈值
```

因此经验条出现25.3之类的小数符合实际累计路径。不能因跳字显示25，就把实际经验写成整数25。

升到满足 `等级 % 3 == 1` 的等级时，反向搜索装备格物品并移除找到的一个“锁定格”，例如4、7、10、13。已有锁格耗尽后不继续凭空扩大格子；表中的条件触发不能解释成无限扩容。

## 6. 怪物基础经验与实际死亡经验

全部42个敌人表物理行都在工作表中，即使没有证明普通层池会选到。基础经验从每行“科学词条.经验”读出；普通不受层成长倍率缩放，精英在 `成长属性` 中把经验词条乘2。

死亡分支 `BP_Actor_Other.ExecuteUbergraph_BP_Actor_Other@L8845` 在匹配“AI.仇恨”或“AI.物品”标签时：

```text
死亡产生经验 = 实际经验词条 × RandomFloatInRange(0.8, 1.2)
游戏模式.增加经验(死亡产生经验, 玩家角色)
```

于是完整式为：

`当前基础经验 × 精英倍率 × 随机系数 × (1+全局经验修正)`。

这里只给数学范围和显式随机输入示例，不声称恢复了所有随机种子与跨系统调用交织。原生 RandomFloatInRange 的端点是否实际可取也不能仅凭 `[0.8,1.2]` 文本确定。随机序列与原生实现证据在随机算法卷中另行标注。

怪物的“价格”字段、材料掉落与装备掉落配置均原样保留；价格不是可以直接当作击杀金币的字段。通用 `死亡掉落` 函数存在 `RandomIntegerInRange(0,Trunc(价格×0.6))` 的调用，但是否由每种具体死亡/交互路径调用必须看调用图，不能无条件套给所有42个怪物。

## 7. 怪物成长率及精英属性

`游戏模式.获取当前层成长率`：

```text
节点等级 = 显式预览等级；若预览等级==-1，则取当前格奖励技能等级，缺有效格/技能时用局部初值1
x = float32((当前总层数 + 额外层数) / 60)
曲线输出 = 敌人属性成长(x)
关卡倍率 = (无尽模式 ? 2.0 : 1.8) ^ 已通过关卡数
节点倍率 = {0:1, 1:1, 2:2, 3:3, 4:4}[节点等级]
成长率 = float32(曲线输出 × 关卡倍率 × 节点倍率)
```

节点等级不在0–4时走Select默认；局部默认值没有另做原生证明，不能把未知等级凭空套进公式。两个源曲线均采用常量前后外推，具体关键帧、切线、插值类型全部保留。

`BP_ManeActor.乘数强化属性` 返回：

`原值 × [1 + 成长率 × 成长率修正 × (角色等级+额外等级)]`。

`BP_Actor_Other.成长属性` 依次执行：

| 字段 | 源处理 |
|---|---|
| 基础伤害 | 成长修正1.0调用一次；精英再×1.2 |
| 生命 | 成长修正1.5**连续调用两次**；精英再×2 |
| 治愈 | 成长修正1.5一次 |
| 护甲（生成护甲参数） | 成长修正1.5一次 |
| 经验 | 普通不变；精英×2 |
| 魔力、最大魔力 | 代码计算精英翻倍，但写入局部临时映射，没有在该函数写回 `self.词条` |

生命实际相当于 `基础生命 × (1+1.5×g×L)^2 × 精英倍率`，并非只乘一次。之后更新最大生命魔力并把当前生命设为最大生命。

分层工作表明确采用“已通关数0、节点等级1、原角色等级1、总层数1–60、普通/精英”作为参考输入；共5040行。它不声称每个敌人在所有60层均可自然生成。另有2440行成长输入组合把节点等级、轮次和无尽模式的关系独立列出。

## 8. 精英判定的调用顺序不能简化

游戏模式 `精英化敌人` 第2227–2268行有两次传统概率判断：第一次决定重置或累加概率，第二次决定返回值。前三层的精英数量上限按0处理，但概率调用仍可能发生。不能把此函数浓缩为“只投一次概率骰子”，否则随机流消耗顺序会不同。本卷的普通/精英数值表把精英标记作为显式输入，不替代这个判定函数。

## 9. 证据与测试

`build_growth.py` 只读取新解包目录，生成全部表；`reference_growth.py` 是独立参考计算，不导入游戏程序或移植代码；`test_reference_growth.py` 验证有限等级无缺漏、全部参数、真实曲线锚点、成长公式、经验小数/显示截断、潜能前置规则及源哈希。

执行：

```powershell
python -I build_growth.py
python -I test_reference_growth.py
```

11组测试与具体向量保存在 `tests-result.json`。这些测试证明本参考实现符合列明的源表达式、输入示例和下述两条成长曲线的原生数值核对；不是完整运行模拟器或原生全局随机流一致性证书。

主要剩余缺口见 `gaps.json`：随机序列交织、逐天赋动态消费方、潜能普通入口可达性、界面缺失原生默认。源原值和字节码在这些缺口处仍保留，不用猜测填空。

## 10. 当前安装包的原生成长曲线核对

本轮进一步静态定位当前 Shipping PE 的数值实现，并在私有内存执行复制出的纯数值代码。没有启动游戏、没有加载原 EXE 为程序或 DLL、没有构造任何引擎对象。

- `UCurveFloat.GetFloatValue` exec thunk：`0x1439b6f50`，直接调用曲线求值 `0x1439882a0`。
- `CurveTable` 求值辅助：`0x143988230`，虚表偏移 `+0x88`；对应虚表 `0x1470a9808` 该槽的指针同为 `0x1439882a0`。
- 两关键帧数值插值：`0x143988940`。
- 无权重三次插值实际采用 Bezier 控制点，再调用 `0x142fabaf0`；控制点转换使用 PE 常量 `0x146be62a0` 的 float32 `1/3`。

最初的普通 Hermite 表达式虽在数学上等价，却与原生运算次序存在末位差异。在20,086个输入比较中曾有10,548个float32不同，最大绝对差约`1.78814e-7`；旧报告保存在 `native/curve-oracle-hermite-comparison.json`。现已按机器码的每条 SSE `mulss/addss/subss/divss` 顺序改写独立实现，且修正内部关键帧正好命中时选右侧区间的行为。

最终 `native/curve-oracle.json` 记录：

- 两条当前曲线各10,043个密集、层级和边界输入，共20,086次 float32 比特比较，全部相同。
- 全部60个英雄经验阈值一致；本次原生核对没有改变此前整数阈值。
- 全部2,440个成长输入组合一致。该比较使用原生曲线输出、当前 PE 导入表确认的 CRT `pow`，再按蓝图双精度表达式运算并做末端float32转换；并非整台蓝图虚拟机的运行回放。
- 当前 PE `GridSnap_Float` thunk `0x143b7cf30` 的实际双精度路径为 `floor((Location + GridSize×0.5)/GridSize)×GridSize`，与本卷正域阈值公式一致。

范围严格限于这两条无权重、常量外推的源曲线及列明输入。加权/循环外推路径未执行，其他曲线不自动获得该证明。代码区间、常量字节和哈希、PE哈希、输入与原生输出都保留，可按 `native_curve_oracle.py` 重现。

## 11. 潜能网格未序列化默认的原生调查

从当前 PE 的 UClass 属性参数确认 `UUniformGridSlot.Row` 位于实例偏移`0x3c`，`Column`位于`0x40`。类注册链`0x14341cf90`指向默认构造辅助`0x14342dfc0`。该构造器写入对齐字段、父/内容指针等，但没有显式写入Row/Column。

因此仅靠该构造器不能证明缺失Row/Column为0：还需核对创建CDO所用分配/零初始化和属性默认复制链。目前没有把缺省值填成0。当前偏移、注册与构造代码保存在 `native/class-addresses.json`、`grid-register.asm`、`grid-construct.asm` 和 `grid-base-constructor.asm`；缺口已缩小为具体的原生初始化链，仍保持未确认。

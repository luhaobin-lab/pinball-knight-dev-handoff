手工房间图不是重新画的示意图。协调者从复制的IoStore解出7×5、140字节BGRA原始数据，见 `studio/reference-session-20261027/room-masks`：01 SHA256 `4ebd5589f8007fe1e20638f89bbe668b396e30161790fdc2f51729551c86757f`，02 SHA256 `1449c8c62228db0cc293ba2dc2ed496f9308ad32cf0ea66f20a4b356336ebde9`。代码只包含B==255的逻辑掩码，不配送原纹理美术。

当前可核查结果：手工01有15个可用房格、由源边界点得144个64uu可走地形格；程序战斗/探索按种子产生不规则边界。房格仍有35个源实例与子出生点，未探索格不参与出生点选择。源固定蜡烛位置保留；蜡烛、罐、火盆、地板图案复用现有程序化美术。棺材阻挡当前仍由现有石墙占位物显示，包围尺寸与碰撞一致。

剩余差异，不能称完整环境复刻：

1. 原动态边界多边形已计算，但运行碰撞接口仍是64uu网格；斜边被栅格化。必须后续升级统一碰撞接口，不能只画斜墙。
2. 首领/教学背景的空气墙子组件旋转、固定碰撞与背景造型未移植；无手工掩码的背景房仍保留旧矩形底图。
3. 迷雾采样/探索展开、回廊增长、地刺/保护罩等环境能力未在本卡实现。计划里存在的危险装饰不会被伪造为已工作的机制。
4. 瓷砖池随机抽取顺序保留，但原TileMap像素构图由批准的程序化换皮替代；并未证明原版所有种子的随机状态完全一致。
5. 自动枝根/壁窗/菌群仍是已有艺术组件；精确原作背景布局与模型对齐尚需更多原版画面对照。`RoomPlan.decorations` 保留旧请求元数据，实际布局以 `placements` 为准。

验证由 `source-room-recovery.test.ts`、room-query、room-exit、core-map及layering覆盖真实mask、随机边界、非法房形、坐标逆变换、源大小、出生点/出口与trace/nativepreview一致。真实浏览器证据保存在 `studio/logs/parity-room-recovery`，不把测试数量或单张图当作完成1:1。

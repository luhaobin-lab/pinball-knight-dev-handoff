   (`withSystems({ … })` from `tests/fixtures/`, or a local fake until `wa/ability`). Missing or wrong facade functions go
   under `needs` addressed to core-contracts.

   are reproduced and marked `// QUIRK (Lnnnn): …` (decision D3).
6. **Translation conventions** for every Demo blueprint you port: ARCHITECTURE §7.2–§7.5 (one module per blueprint,

   classes in `src/content/bp/batches/<card-id>.ts` (pre-created empty by core-contracts).
7. **Done means**: `npm run check` green in your worktree (typecheck incl. `src/core`, all tests incl. purity and
   layering), your acceptance tests pass or are listed as SPEC-GAP with the reason, `git diff --name-only` shows only your
   paths, result schema filled (`target`, `proposals`, `needs`, files, commands run with results, open issues).
8. **Review**: one code reviewer per card (target card, ownership, spec vectors, SPEC-GAPs), at most 2 fix rounds;
   style issues go to the backlog. A fix round may be used to rerun your vectors against the merged foundations.
9. **Git hygiene**: many worktrees share one repository; if a git command fails on a lock (`index.lock`, `unable to lock
   ref`), wait a few seconds and retry. Leave no processes running.

## 3. Contract amendments (core-contracts implements them; everyone codes against them)

ARCHITECTURE Appendix A is the contract, with these changes:

1. **Screens**: `screen: 'title' | 'heroSelect' | 'map' | 'room' | 'runEnd'`. The Demo's camp *is* the main menu (phase 14,
   `UI_营地主菜单`); there is no `death` (soul-ball scene is dead) and no separate `camp` screen.
2. **Commands** (A.8): remove `title.continue` (继续冒险 is always hidden), `hero.abyss` (abyss levels are collapsed),
   `camp.*`. Add `title.settings`, `map.option { option }` (the chapter page's `UI_关卡选项`, e.g. 营地),
   `warning.answer { button: 0 | 1 }` (回忆 / 遗忘, 重置房间 / 放弃探险 …), `page.open { page }` / `page.close` for pages
   wave B fills (`craft`, `materials`, `stash`, `codex`, `talents`, `settings`). `skill.press { slot: number }`.
3. **Modals** (A.8): `multiChoice.source: 'levelUp' | 'unique' | 'initialReward' | 'boss' | 'scroll' | 'event' |
   'ultimateChoice'`; `warning.type: 0 | 2` with the Demo texts and buttons (PROTOTYPE_SCOPE §2); `runEnd` carries
   `{ lines, score, exploration: { level, progress, need }, demoComplete }`; remove `death`.
4. **GameOptions.debug**: `{ floors?, chapter?, hero?, skipPrologue?, unlockAllHeroes?, forceItems?, forceTalents?,
   forceEnemies? }`. `skipPrologue` sets the save flag `新手关过？` so 新的冒险 shows.
5. **World** (A.5) gains `latent: LatentService` (core-sim implements; `BpObject`'s latent helpers delegate to it),
   `filter: 'ported' | 'all'` and `isRowPorted(table, row)` (a row is ported when every class its manifest entry
   references is registered). Modules that draw from pools (map tiles and variants, item and talent offers, drops) skip
   unported rows under `'ported'`.
6. **Declarations are generated** (decision D8). `tools/gen/facade.mjs` emits, from the pseudo `var` and `function`
   lines of the 19 system classes, the TS classes with CDO-default fields and one method per Demo function:
   `造成即时伤害(…) { return this.world.sys.damage.造成即时伤害(this, …) }`. Library functions take the calling object
   as `ctx`. A missing module function calls `world.unported('<Class>.<fn>')` and returns the neutral value of its return
   type (strict mode throws). Pure library math (`函数库_科学数`, PRD/weights) delegates straight to `src/core/math`.
   `present` functions are generated as no-ops; `dead` ones as unported.
7. **Module set** (`src/core/sys/<module>/`, one owner each): Appendix W2. It splits Appendix B's kernel into `sim`
   (core-sim) and `kernel` (core-ability), and adds the wave-B modules `craft`, `enchant`, `shop`, `camp`, `tutorial`
   (stubs until wave B) with the functions W2 moves out of `inventory`, `rewards`, `turn` and `meta`.
8. **`view.room` is the `RoomPlan`** from core-map (grid 5 × 7 tiles of 64 uu, solids, decorations, spawn deck, task,
   player spawn, background).

## 6. Merge-train rules

1. **Who**: only the integrator touches `main` (merge commits, never rebases of `main`). Cards are merged after their one
   review passes (or after their last fix round).
2. **Order**. T1 (target t+3:00): core-contracts → core-math → core-sim → core-ability → content-bpkit → ui-kit → ui-pages
   → tools-bot → core-map → core-inventory → game-shell. T2 (target t+5:00): core-damage → core-status-rating →
   core-stamina → core-physics → core-turn → core-ai → core-launch-sys → core-rewards → core-talents → core-run. T3: game-g2
   (and its `g2-fix-*` cards). A card whose dependencies are not yet on `main` waits for the next train.
3. **Per-merge gate (≤ 3 min)**, on the branch merged with `main`: `npm run check` (tsc × 2 + vitest, incl. purity and
   layering), `npm run data:check`, the ownership check (`git diff --name-only main...task/<id>` against the card's
   paths, after the foundations are on `main`). Before T2 the bot gate is the fake game plus the real `createGame` smoke
   run. In T2, `npm run bot -- --runs 200 --policy random --filter ported --workers 18` and `npm run bot -- --determinism
   10` run and their reports are attached, **warn only** (the loop is wired in G2); from T3 on they block (0 crashes,
   0 softlocks, determinism equal).
4. **Per-train gate (≤ 15 min)**: the merge gate, plus `npm run bot -- --runs 1000 --compare <last report>` (from T3), the
   coverage report, `npm run build`, `npm run shots -- --scene game-loop …` for the screens that exist, `npm run perf --
   --scene game-loop --seconds 10`, `npm run golden` (warn only).
5. **Failure**: revert the failing merge (and any later merge of that train that depends on it, in reverse order), keep
   `main` green, send the card a fix round with the failing test or seed and command log. A card that fails twice is
   re-planned (split or different approach, plan v4 §6).
6. **Alarms** (compared with the previous train's report): any crash or softlock, a determinism mismatch, a coverage
   drop, win rate or floors per run moving more than 15 % without a balance-relevant merge, the test suite over 60 s.
7. **Shared files**: the integrator applies `needs` to shared files (`package.json`, `src/main.ts`, `src/debug/router.ts`,
   `tools/**` outside delegated paths, `studio/OWNERSHIP.md`) during the train, and after T1 updates OWNERSHIP.md with the
   module folders of Appendix W2 and the new lanes `tools` (bot) and `bp` (content modules).
8. **Retro**: after T3 the orchestrator writes the wave retro (cards done, average time, rework rate, bot defects,
   blocked time, spend) as plan v4 §6 requires.

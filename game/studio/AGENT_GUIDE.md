# Agent Guide — 《棺材板下》 studio (v3, 2026-10-22)

Read this before doing anything. Read `studio/CODEX_WORKFLOW.md` next; its approved takeover rules supersede historical scheduling and path instructions. Then read `studio/ART_BIBLE.md` and the documents your task names.

## What we are building

An H5 roguelike (Three.js / WebGL2, TypeScript, Vite) that recreates the **Ricochet Abyss Demo** 1:1:

- **Copied 1:1** (the producer states the company holds the rights): mechanics, algorithms, numbers, UI layout and
  content counts.
- **Reskinned with our approved art**: a corrupted fungal world explored by the beetle knight (甲壳虫骑士), rendered as
  procedural 3D pixel art at 960×540.

The plan is `方案-v4-原型优先.md` (prototype first: the complete 30+ minute game 1:1 with placeholder art, polish later; work fast, never grind on details); the wave plans are `studio/PROTOTYPE_SCOPE.md`, `studio/ARCHITECTURE.md`, `studio/WAVE_A.md`, `studio/WAVE_B.md`; v3 `方案-v3-自动化工作室.md` still defines the studio conventions; the art standard is `studio/ART_BIBLE.md` with the golden frames in
`studio/golden/`.

## Hard rules

1. **Two sources of truth, nothing else.**
   - Rules and numbers come from verified specs (`spec/`) and from the Demo data imported into `src/content/demo/`.
   - Visuals come from the art bible and the golden frames.
   - Never invent mechanics, numbers or styles. If the spec is missing or unclear, implement the closest documented
     behaviour, mark the code `// SPEC-GAP: <what is unknown>` and list it in your result.
2. **Target card first.** Start every task by stating, in your result's `target` field:
   - which part of the Demo it reproduces (dump/spec paths);
   - the acceptance tests;
   - which golden frame it must match (visual tasks);
   - which forbidden items apply.
   Reviewers check the target card before the code.
3. **Proposals, not surprises.** Ideas beyond the task go under `proposals` in your result. Do not implement them.
4. **Everything shipped is generated by code at runtime**: geometry, textures, shaders, particles, UI, icons, audio.
   - No external images, models, sprites, textures or audio files.
   - Exception: an OFL pixel font with CJK coverage (subsetted).
   - AI images may only be internal references, never shipped.
5. **The core simulation (`src/core/**`) is deterministic and pure.**
   - No DOM, no three.js, no `Date.now`/`Math.random` (use the seeded RNG), no frame-rate dependence.
   - The aim preview must equal the real result.
6. **Only edit files inside your task's owner paths** (`studio/OWNERSHIP.md`), plus your tests and debug scenes.
   Anything else goes under `needs`. Never reformat or rewrite unrelated files.
7. **No new npm dependencies** unless your task says so; request them under `needs`.
8. **Git and worktrees.**
   - Code tasks never edit the main checkout. Create (or reuse) your worktree with
     `bash D:/TAPTAPGAME_codex/project/studio/bin/wt.sh <task-id>`. It prints the path
     (`D:/TAPTAPGAME_codex/project/.codex/worktrees/<task-id>`, branch `codex/<task-id>`).
   - Work, build, test and commit only there. Start every Bash command with `cd "<path>" && ...` and give Edit/Write
     absolute paths under it.
   - Commit message: `<task-id>: <summary>`.
   - Never push, never touch `main`, never run `git add -A` in the main checkout. Only the integrator touches `main`.
9. **Never modify anything under `D:/steam`** (the Demo). Read `D:/TAPTAPGAME_codex/reference/` freely.
10. **Clean up owned processes.** Tools must stop their servers and browsers. The producer-authorized Codex heartbeat may persist; its identity and control state must be recorded. Never revive old Cindy workflows.
11. **Look at your work.** Visual tasks render screenshots with `npm run shots` and look at them, at full size and
    next to the matching golden frame, before reporting.
12. **Environment**: Windows 11 with Git Bash. Use forward slashes and quote paths that contain spaces or CJK.

## Commands

- `npm run check`: typecheck (including the `src/core` tsconfig) and unit tests.
- `npm run shots -- --scene <name> [--t s] [--frames n --interval s] [--query "k=v"] [--out dir] [--nobuild]`:
  Chrome screenshots. Frames are named `<scene>-NN.png`; sort them numerically.
- `npm run perf`, `npm run build`, `npm run package [-- --scene <name> --out <dir>]` (single-file HTML in
  `delivery/`, or `<dir>/index.html`).
- `npm run review -- --scene <name> --stills t1,t2 --clip s [--out dir]`: the review pack (stills, MP4, GIF).
- `npm run golden`: visual regression against `studio/golden/`.
- `npm run data:import` / `npm run data:check`: regenerate or verify `src/content/demo/` from the Demo dump.
- All options are in `tools/README.md`.

## Quality bar

- **Fidelity**: behaves and reads like the Demo. Numbers match its tables. The layout matches its widgets.
- **Visual**: indistinguishable in style from the golden frames. Hero, enemies and background are separable at a glance.
- **Code**: TypeScript strict, small modules, no dead code, comments only where the intent is not obvious.
- **Performance**: 1080p at 60 fps on this machine with headroom; quality tiers for mobile.

# 方案 v4：原型优先（2026-10-23）

> 制作人指示：先用最快的效率做完一个完整的游戏原型，至少有半小时完整、流畅、和原版体验完全一致的游玩；
> 重点是角色、怪物、玩法、机制、装备、协同效应、关卡。美术、动作、手感等优化放到原型之后。
> 工作室要定期自我评审、持续提效，不在一个小地方死磕。
>
> 本方案取代 v3 的生产顺序（v3 的美术标准、目录归属、工作树规范继续有效）。

## 1. 原型的定义（验收标准，即 G3）

- **完整一局**：主菜单 → 选英雄 → 序幕（教学）→ 章节地图 → 多层房间（战斗 / 精英 / 事件 / 商店 / 宝箱 / 经验 / 休息等）→ 首领 → 胜利或死亡结算 → 营地（局外成长）→ 再开一局。
- **内容**：Demo 里能玩到的全部英雄、敌人、首领、装备、天赋、附魔、诅咒与祝福、事件、道具和机制。数值全部来自已导入的 Demo 数据表（49 张表，2546 行）。
- **时长**：一局 ≥ 30 分钟，层数和节奏与 Demo 相同。
- **一致性**：同样的选择得到同样的结果。公式、触发时机和结算顺序以 Demo 蓝图为准；机器人对局的统计结果与按 Demo 规则推导的结果一致。
- **质量**：机器人连续跑 1000 局，无崩溃、无卡死；1080p 60 fps；存档可以续玩。
- **不要求**：美术细节、动画、打击感、音效。已经做好的保留，新内容先用占位。

## 2. 复盘：之前为什么慢

| 问题 | 例子 | 代价 |
|---|---|---|
| 在单点上反复打磨 | 瞄准线的像素细节评审了 3 轮，留下 26 条美术意见；手感波次深挖特效 | 时间花在玩家几乎感知不到的地方 |
| 评审比开发重 | 每个任务 3 位美术评审 × 最多 3 轮 | 评审耗时超过开发 |
| 规格先行、任务太碎 | 先写规格、再开发、再集成，串行等待 | 并行度低 |
| 依赖人工看图 | 截图对比金标帧 | 慢，而且发现不了玩法问题 |

## 3. 新做法（提效原则）

1. **玩法优先，美术冻结。** 沿用已批准的画风和现有模型（甲壳虫骑士、4 种小怪、地牢房间、墨与骨 HUD）。新的怪物、首领和道具一律用程序化占位：剪影、色块加名字。界面先做功能版。
2. **数据驱动加效果解释器。** Demo 的内容就是数据表加效果蓝图（能力 129 个、效果 446 个、发射物 12 个）。先做通用的能力/效果框架，再把蓝图按批次机械翻译成 TypeScript，每个代理一批 15–20 个并附测试。内容可以大规模并行铺开。
3. **蓝图伪代码就是规格。** 内容类单元（物品、天赋、敌人技能、事件）不再单独写规格文档，代理边读伪代码边实现，在代码里标注出处。只有系统级模块用已有的草稿和规格：回合流程、伤害、能力框架、地图生成、背包。
4. **自动化验收代替人工评审。**
   - 核心逻辑是纯函数；无头机器人每次合并都自动跑整局对战，检查崩溃、卡死、耗时、伤害与胜率分布，并做数据一致性测试。
   - 评审只保留 1 位代码审查，最多 2 轮修复；剩下的小问题记入待办，不阻塞。
5. **大颗粒、纵向任务。** 一个任务负责一个完整系统：数据 → 规则 → 最简界面 → 测试，减少交接。
6. **持续集成。** 每 2–3 小时开一班「合并列车」，把通过的分支合进 main 并跑全量回归，main 始终可玩。
7. **时间盒。** 每个任务 ≤ 3 小时。卡住就按「最接近的已知行为 + SPEC-GAP 标注」交付，问题进待办，继续往前走。

## 4. 阶段与排期（预计 4–6 个工作日出原型，受每日额度影响）

### 第 0 步：范围审计（2–3 小时，1–2 个代理）
列清 Demo 实际能玩到的内容：开放的英雄、章节、层数、房间类型、首领、物品池、天赋池、事件。产出「原型内容清单」和模块依赖图，作为后面所有任务的清单。

### 波次 A：系统骨架（约 1 天，约 12 个并行任务）
- **能力/效果框架**：时机标签（效果.时机.*）、条件、参数（科学数、获取技能参数）、持续时间、叠层、事件总线。
- **战斗回合**：
  - 玩家回合，复用已经 1:1 的弹射核心；
  - 敌人回合：AI、意图、行动顺序；
  - 伤害管线：暴击、弱点、吸血；
  - 战斗状态：护盾、格挡、闪避、易伤等；
  - 体力、腐化、精神状态（规格已验证）。
- **背包与装备**：网格、尺寸、放置；充能、灌注、回响、耐久。
- **地图与房间**：章节、层、节点、房间类型的地图生成；房间形状、刷怪点、陷阱与装饰的房间生成；房间进出流程。
- **奖励与成长**：掉落、宝箱、经验与升级、升级时三选一天赋、货币。
- **功能版界面**：地图页、战利品窗口、物品提示与右键菜单、天赋选择、胜利/失败结算、英雄选择、最简营地。
- **测试与表现**：无头机器人和回归框架；表现适配层，把核心事件接到现有渲染（占位怪、伤害数字、简单特效）。
- 🔶 **G2 审核**：一条「最薄的完整链路」可玩（开局 → 地图 → 战斗/事件/宝箱 → 首领 → 结算 → 营地），内容先放少量。

### 波次 B：内容铺开（约 1.5–2 天，约 30 个并行任务，分 2 批）
- 效果蓝图移植（446 个，约 25 批）和能力蓝图（129 个）。
- Demo 全部敌人（含 AI 技能）和首领（含多阶段）。
- 全部装备（约 200 件）、天赋（147 个）、附魔、诅咒/祝福、事件/商店/雕像/铁砧、合成、陷阱/装饰/拾取物。
- 英雄：Demo 开放英雄的技能、被动、专属物品和专属天赋。

### 波次 C：完整性与一致性（约 1 天）
- 序幕教学流程、存档与读档、设置。
- 机器人 1000 局，做平衡与一致性比对；全内容覆盖测试：每件装备、每个天赋至少被触发一次并结算正确。
- 制作人试玩后的修复轮。
- 🔶 **G3 审核**：≥ 30 分钟的完整一局，体验与 Demo 一致。

### 原型之后
统一设计全部英雄、怪物、首领的美术（即 v3 的 G3），然后是动作和手感（接着用已封存的 6 条手感分支）、音效、本地化与正式命名。

## 5. 审核节点

- **阻塞节点只留两个**：G2（完整链路）和 G3（完整原型）。照旧发可玩链接加 GIF，你确认后再继续。
- **每天一个「当日版本」链接，不阻塞**：你可以随时看、随时纠偏。

## 6. 自我迭代机制

- **每个波次结束自动出复盘**：完成任务数、平均耗时、返工率、机器人发现的缺陷、阻塞时长、额度花费，并和上一波次对比。
- **按复盘调整下一波**：任务颗粒、并行度、评审深度、提示词模板。常见错误写进工作手册，避免重犯。
- **硬规则**：
  - 任何任务失败两次，就换方案或拆小；
  - 原型阶段的美术和手感意见一律进待办；
  - 同一个问题最多修 2 轮。
- **目标**：每一波「每小时完成的内容单元数」都比上一波高。

## 7. 风险

- **每日额度（约 1500 美元）**：内容铺开波次可能触顶，触顶后在次日 08:00 自动续跑。
- **翻译量大**：除弹射外的逻辑都在蓝图里，翻译量大但可以完全并行。少数引擎行为（物理、粒子）按「最接近的已知行为」实现并标注。
- **原型不好看**：这是有意为之，先保证可玩和一致，美术在原型之后统一做。

## 8. 现状盘点（可直接复用）

- 1:1 弹射与碰撞核心（已和实机逐帧核对）、Demo 全部数据表的导入、墨与骨 HUD、参考战斗房间、审核与打包工具、491 个测试。
- 已验证的规格：回合流程、体力/腐化/精神状态。另有 17 份规格草稿：能力框架、伤害、状态、充能、敌人 AI、3 组敌人、3 档首领、英雄技能、评级等。
- 封存待用：手感波次的 6 条分支（规格、震屏、特效、角色反应、程序化音效、界面动效）。原型完成后继续。

# 项目 UI 宪法 · 手机迭代 02

版本：2026-10-29。状态：本轮设计与原型约束，待用户视觉审阅；不等同于已接入游戏的生产规范。

本文件优先于全集01的桌面尺寸、旧字号、密集常驻容器和金色主按钮建议。功能与数值边界以同目录《需求与数据边界.txt》为准。来源事实与设计建议的区别见《移动端依据.txt》和《来源.json》。不得把本轮选择追溯写成用户已批准的历史规则。

## 1. 项目与目标

- 类型：装备构筑、弹射战斗、搜打撤式地牢冒险。
- 平台与输入：手机横屏，触控为主；浏览器鼠标点击只用于原型检查。
- 画幅：20:9；逻辑基准800×360；高清交付3200×1440，为4倍像素密度导出。
- 语言：简体中文。信息密度：战斗低、整备中、详情通过滚动逐步披露。
- 视觉关键词：墨黑、纸灰、骨白、粗轮廓、克制暗红、哥特暗黑。
- 核心目标：先看见当前任务与选中对象，再读支持信息；重要操作足够大且后果明确。
- 本轮内容：12页视觉候选与组件原型，不修改玩法，不假装具有完整经济或成长配置。

## 2. 体验与内容原则

1. 战斗关注敌我与瞄准区域；装备与背包提供查看，不能在等待发射时偷换成可整理状态。
2. 营地提供整理、保险箱、天赋培养和层选择。解锁消耗技能点，升级消耗金币，仅营地可培养。
3. 商店围绕选择商品或出售对象展开。点击物品只选中；明确的购买/出售动作才提交事务。
4. 只保留装备栏位、英雄属性、装备图鉴三个全局页签。英雄属性与角色天赋同屏；装备图鉴不含天赋。
5. 物品名称、机制与品质版本必须一致。未知价格、成长费用、等级上限和下级效果省略，不能填0、免费或任意数字。
6. 不新增锻造、附魔、加工、洗点、合成、商店刷新、买回、多人、每日任务、新货币和分叉路线地图。
7. 数据来源、设计样例和开发说明放在图外说明文档，不作为游戏中的假信息。

## 3. 字体与字号

中文、英文及数字均使用同一字体体系：PingFang SC；缺失时使用系统sans-serif替补。跨平台替补字体必须重新检查字宽、换行和行高；不能把macOS截图结果当成Android字体结果。

实际游戏稿使用400常规、600半粗两档；不得再逐页添加字重。数字使用等宽数字特性（字体支持时），右对齐或固定位置，不额外引入数字字体。

| 令牌 | 逻辑字号 | 4倍导出像素 | 语义 |
|---|---:|---:|---|
| T1 | 12 | 48 | 非必要、非交互的辅助注记；不能用于价格、主要数值、按钮或机制正文 |
| T2 | 14 | 56 | 次级正文、支持说明、次要状态标签 |
| T3 | 16 | 64 | 主要正文、常规按钮、重要数值；列表次级物品名使用14，选中详情标题使用20 |
| T4 | 20 | 80 | 关键操作、分组标题 |
| T5 | 24 | 96 | 页面标题、当前选中对象标题 |
| T6 | 32 | 128 | 少量强调数字或低频标题 |

不得临时增加第七档字号。长文本先换行、扩展或滚动，不靠缩字。行高通常为字号的1.35–1.5倍；同类组件一致。正文前景与实际背景按4.5:1核对，大标题至少3:1；纹理叠加后也要复查。

## 4. 布局与安全区

逻辑单位均指当前原型的CSS坐标，不是导出图物理像素；正式移动端需核对引擎单位与dp/pt的映射。

- 基础间距网格：4；常用间隔8、16、24。
- 水平设计内边距：24，与运行时系统安全区取最大值（例如max(24px, env(safe-area-inset-left/right))）。安全区随设备和方向变化，不是固定24即可替代。
- 基准800宽、尚未加额外系统inset时：左侧136、区间16、中央448、区间16、右侧136，两端24。
- 左区x=24至160；中央x=176至624；右区x=640至776。
- 基础格：56×56；格间8；栏内左右8。一件整装备跨两格，宽120，作为一个完整物品块，内部无竖向中缝。
- 装备可占1至3个纵向基础行，连续物品只有上下排序语义。不得把横跨两格误画成两件并排装备。
- 右侧背包保持两格宽，纵向滚动；长内容只在指定容器内滚动。
- 顶部页签高48，固定顺序：装备栏位／英雄属性／装备图鉴。标签采用真实文字与选中标记，不依赖小图标。
- 顶部右半显示生命、体力、腐化、金币；资源条为静态状态，不伪装成可点击按钮。0腐化显示空槽。
- 英雄页扩展至左区加中央共600宽；左侧人物属性、右侧角色天赋同时可见，右背包继续独立存在。
- 明显表面容器最多两层。先用空白、对齐和分隔线分组，再考虑围框。
- 遇更窄可用区或更大的系统inset时，先重排/收纳次要内容并允许详情滚动，不能整体缩到热区和字号低于约束。

### 商店的本轮布局选择

商店左侧136用于商人剪影与当前模式氛围，中间448用于商品与详情的大任务区，右侧136用于两格背包。装备常驻网格在商店暂时收起，顶部装备入口仍保留；离开商店恢复原装备展示。

这是为扩大手机交易阅读区采用的本轮方案，供用户审阅；不代表删除装备系统，也不冒称用户已明确批准取消常驻网格。不得把商人插画重新放大到挤压商品说明和动作。

## 5. 色彩与表面语义

以下色值已与本轮ui.css同步。功能色复用；局部面板使用同色相深浅层级，不逐页生成独立皮肤。

| 令牌 | 初始色值 | 用途 |
|---|---|---|
| background | #0C0D0E | 墨黑底色与留白 |
| surface.primary | #181918 | 主面板哑光表面 |
| surface.secondary | #222321 | 选中对象/次级表面 |
| text.primary | #E6DFCA | 骨白正文与主要信息 |
| text.secondary | #B2B0A3 | 纸灰支持文字 |
| text.disabled | #8D9384 | 非关键禁用文字；禁用原因仍清楚可读 |
| action.primary | #A52E31 | 暗红主要操作；配骨白文字 |
| action.secondary | #242721 | 次要操作 |
| action.danger | #A52E31 | 与主操作同色体系，必须另配明确危险动作和后果文案 |
| state.success | #71ACA2 | 成功标记，配文字/图形 |
| state.warning | #AD9160 | 警告，配文字/图形 |
| state.info | #71ACA2 | 支持性信息 |
| decorative | #AD9160 | 低对比旧金材质，仅局部边缘，不用于主按钮 |
| overlay | rgba(0,0,0,0.72) | 详情背景压暗 |

暗红面积负责当前主要操作，金色只做弱材质。本条覆盖《视觉评估标准.txt》中早期“赭金作为主要动作”的建议。不要把所有选中、状态条和装饰都涂成主动作色。

表面平整哑光，普通区域最多一层细线，不画每格角花、连续金属亮边、霓虹描边或玻璃反光。插画中可有局部粗黑影与干笔，但文字底下不得撒纹理噪声。直角为主；统一最多4逻辑单位小切角，不能随机缺角伪装手绘。阴影只用于层级，不重复抬高每个槽位。

## 6. 组件与输入

| 组件 | 规则 | 必要状态 |
|---|---|---|
| 主按钮 | 单任务区最多一个；动作+对象；高频优先56高，至少48高 | 默认、按下、禁用、处理中、成功、错误 |
| 次按钮 | 低于主动作；关闭/返回与取消可直接理解 | 默认、按下、禁用 |
| 页签 | 高48；真实标签；选中同时有底色/标记与语义状态 | 默认、选中、按下 |
| 装备块/背包物品 | 基础格56、整件宽120；图标+按需名称，选中不移动物品 | 默认、选中、锁定、空、内容溢出 |
| 详情面板 | 标题、主要效果、支持信息分层；长文内部滚动 | 普通、长文、内容缺失的图外标注 |
| 关闭控件 | 至少48×48热区，避开系统inset；不能靠细小X本身充当热区 | 默认、按下、焦点 |
| 反馈条 | 成功或错误用文字说明动作结果；不遮挡同页后续操作 | 成功、错误、可恢复 |
| 资源条 | 标签、数字、填充一致；0值不填满 | 正常、低值/危险（真实状态驱动） |

独立相邻热区至少8间隔，不相互覆盖。触控不依赖悬浮；鼠标hover只能是附加反馈。陌生关键图标配文字。焦点态用于原型键盘检查，但不改变手机主要布局。

未知价格/费用的视觉候选只能表达构图与资源类型，不能提供假报价，也不能称为完整的交易决策演示。真实版本必须拿到报价和空间校验结果后才能提交；在缺失数据时不得扣款、转移物品或宣称成功。本轮的图外限制说明不能伪装为玩家会看到的生产错误文案。

## 7. 图标与美术

沿用已核验物品身份与原有图标；同类缩放、边框、阴影和渲染策略一致。插画不是控件，不通过发光边框制造可点击暗示。角色/环境氛围可由Sunburst制作；所有文字、按钮、格子、标记与页面状态由统一组件排版。

主参考：《暗黑地牢》官方补给截图中的黑色分区、局部骨白、商人剪影、强弱格区别。只借鉴视觉属性，不复制商人造型、专有图标、经济与PC密度。

辅助参考：《死亡细胞》官方移动版的触控重排方法；《神之亵渎》的暗黑像素空间与克制材质。不得把其他游戏的动作按键、药瓶、队伍、职业、疾病或额外资源加入本项目。

## 8. 动效约束

- 标签/选中反馈：即时响应，约80–120毫秒，不阻塞输入。
- 普通详情：约120–160毫秒淡入或短位移；关闭同样迅速。
- 交易/领取结果：仅当实际状态改变后显示；不能以动画掩盖未完成请求。
- 不使用持续扫光、边框呼吸或每格粒子。减少动画时取消位移，仅保留状态变化。
- 以上是生产要求；静态图不构成动效验证。

## 9. 已知、样例与待验证

已知：最新用户功能要求；已保存真实战斗样本与目录记录；三件物品的当前实例/青铜目录区别。

样例：角色天赋解锁/升级外观、选择节点、层1已通关/层2选中/层3锁定等。样例不是当前存档，也不建立成长前置、解锁费用、上限或新游戏开局经济。

待定：全部新商店报价、卖价、天赋费用/等级曲线、完整存档状态；未领取奖励关闭后的规则等。

待验证：真实手机点击与遮挡、系统手势、安全区、字号设置、跨平台替补字体、新用户路径、价格信息完整后的交易判断。脚本点击、DOM尺寸和高清截图只能提供相应技术证据。

## 10. 审阅与变更

本轮先按任务、布局、信息、状态检查，再审美术。出现文字不可读、主要动作不清、热区重叠、内容版本混用或虚构数据时退回对应层，不用视觉优点抵消。

不填写虚构综合高分，不声称已完成真机或新用户验收。提交时分别列出：已做的静态/技术检查、已知缺口、尚未进行的用户测试。

本轮实际费用缺失态：商店显示“暂无报价”并禁用买卖；培养仅标明所需资源和空值并禁用。它们是设计数据尚未定稿的可审阅状态，不代表已有服务正在报价或玩家资源不足。

手机横屏 UI 第二轮：来源、设计约束与验证边界
核验日期：2026-10-29（Asia/Shanghai）

一、已查证的来源事实

[S01] Google Android 无障碍帮助建议可点击区域至少 48×48 dp，相邻热区间隔至少 8 dp。可见图标可以比热区小；例如 24 dp 图标通过内边距获得 48 dp 热区。扩大热区不能造成相邻区域重叠。
https://support.google.com/accessibility/android/answer/7101858?hl=en

[S02] Google 面向游戏的 Playables 设计建议同样使用 48×48 dp 热区和 8 dp 间隔，并要求文字/图标适应不同尺寸、区分按钮状态。普通较小文字使用至少 4.5:1 的对比度；大文字可使用 3:1。它是平台设计建议，不是对所有游戏统一生效的法定标准。
https://developers.google.com/youtube/gaming/playables/certification/best_practices_design

[S03] Apple HIG Layout 要求按内容重要性组织、通过对齐和空白分组、渐进披露次要信息；即使固定横屏，游戏也要适配尺寸变化。安全区由系统和硬件决定，用来避开屏幕边缘硬件或系统视图，不能用一套固定边距声称覆盖所有设备。
https://developer.apple.com/design/human-interface-guidelines/layout
核验方式：官方页面提供的 layout.md 正文，使用正常 HTTPS 读取。

[S04] 当前 Apple HIG Accessibility 表中，iOS/iPadOS 控件推荐默认尺寸是 44×44 pt，最小值是 28×28 pt；字体默认 17 pt、最小 11 pt。这不是“所有手机文字都应做成11”的建议，也不能将44误写成当前文档的硬性最小值。
https://developer.apple.com/design/human-interface-guidelines/accessibility
核验方式：官方 accessibility.md 正文。

[S05] Android 文档区分像素、dp 和 sp：屏幕密度不同，相同物理像素数对应的物理尺寸不同；布局使用 dp，文字使用能响应用户字号偏好的 sp。静态图片分辨率不能证明触摸区域大小。
https://developer.android.com/training/multiscreen/screendensities

[S06] 《死亡细胞》移动版的开发者商店说明明确提到为手机重做界面，并支持改变按钮位置与尺寸；Playdigious 帮助站也列出辅助模式与相关控制选项。此处只借鉴“围绕触摸输入重新分配界面”的方法，不把移动、跳跃、翻滚或自动攻击加入本项目。
https://apps.apple.com/us/app/dead-cells/id1389752090
https://playdigious.helpshift.com/hc/en/7-dead-cells/section/35-settings/?p=android

[S07] 《暗黑地牢》官方媒体页与官方 Steam 截图可作为美术参考。已实际查看本项目保存的补给截图 R2：画面大面积黑底，商人形成明显剪影，商品图标与价格对齐，空槽弱化，选中槽局部强调。此处“黑底、剪影、空槽弱化是可借鉴的优点”属于视觉分析，不是制作组公开声明的设计法则。
https://www.darkestdungeon.com/darkest-dungeon/media/
https://store.steampowered.com/app/262060/
原图、SHA-256 和本地路径见同目录 来源.json。

二、本项目本轮采用的设计建议（非来源原文）

1. 先在 800×360 的逻辑画布设计，20:9；4倍导出成 3200×1440。48逻辑单位的热区对应导出图192像素；8逻辑单位间隔对应32像素。16逻辑字号对应64导出像素。反之，在3200图上做48像素按钮，缩到800宽后只有12像素。
2. 浏览器原型用 CSS px 管理逻辑尺寸，但 CSS px、Android dp、iOS pt 不能在任何缩放条件下都直接等同；正式移植必须按引擎缩放、视口、设备密度与安全区重新核对。
3. 初始字号固定为 12/14/16/20/24/32 六档；16用于正文和常规按钮，20用于重要动作，14用于辅助说明，12仅用于非关键注记。若手机尺寸下中文显小，优先减少内容或增大字号，不缩字塞满。
4. 可交互热区至少48×48逻辑单位；高频关键操作优先56高。邻近独立按钮尽量留8逻辑单位。两格背包的基础格至少48；若两格只承载一件整宽装备，按一个整体热区处理，不能画成两件独立物品。
5. 左装备、右背包、顶部状态保持稳定；英雄属性与装备图鉴通过足够大的文字入口展开。商店是当前任务主屏，商品、选中详情、购买/出售动作获得主体空间，角色插画退为局部氛围。
6. 主要操作使用一个最高强调按钮；价格与动作靠近；资金不足要同时给文字原因与不可操作状态。长描述用滚动区域或分层展开，不把所有机制放进物品小格。
7. 先检查灰度下标题、选中对象和主要动作是否一眼可分；再叠加黑色墨块、粗轮廓和有限的骨白/暗红强调。磨损与笔触放在局部大形体，不让每个小格都拥有同样的金属边、角花和辉光。
8. 本轮“减少AI味”落实为可检查的限制：同一字体、同一格制、可复制的组件、真实文字、固定数字对齐、有限材质、可解释的非对称构图。不能以“看不出AI”作为已经被证明的事实。

三、进入最终视觉前的检查

每一页先回答：玩家在哪里、当前要做什么、按哪个按钮、按后发生什么、失败如何返回。
检查主要文字与底色对比度、所有按钮边界、触摸区是否相交、关闭按钮能否点到、滚动内容是否有提示。
同一物品跨战斗/营地/商店/图鉴的名称和机制必须来自对应样本，购买价/节点费用等未确定数字不得臆造。
同一画面最多一个主要动作。默认、按下、选中、锁定、禁用、空、溢出以及错误恢复的外观应有规则。

四、尚未完成的验证

浏览器截图与DOM热区测量只能证明该原型在该视口下的布局；不能证明手机实际触感、手指遮挡、系统手势冲突或新手可用性。
须在实际横屏手机检查至少一个小屏和一个带屏幕开孔的机型；记录视口、缩放、系统安全区、是否使用系统字号放大。
新用户测试任务：打开英雄属性、找到淬毒利刃详情、在商店识别商品与价格、理解资金不足、返回战斗。记录首次有效操作时间、误触、回退和误解，不引导玩家点击正确答案。
本文件没有声称完成手机实测、盲测或美学验收。

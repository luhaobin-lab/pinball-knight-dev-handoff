3. 原制作方法
先保留名称、功能、占格和未知项，再写每件独立提示词。
以已认可的三件样稿或风格板，以及《风暴怕死队》官方裁图约束墨线、色块、形体和阴影。
使用内置image_gen逐件生成透明高分辨率母稿；不是用程序几何替代具体物品。
像素化采用预乘透明的等比Lanczos缩放、轻微锐化、无抖动Median-cut限色、alpha阈值128。
128档最多64个可见色，256档最多96个可见色，透明值只保留0/255。
每边至少留宽度1/32的透明边距；2×1、2×2、2×3按画布比例保留。
最后核对PNG尺寸、透明、边距、哈希、逐件画面与图集切片。
references保存实际裁图与来源；不把官方人物、UI、功能或资源当成可运行资产使用。

4. 跨机环境
使用Python 3.11+，在当前目录执行：
  python3 -m venv .venv
  .venv/bin/python -m pip install -r requirements.txt
Windows将后续python3换成.venv\Scripts\python.exe；macOS/Linux可使用.venv/bin/python。
为便于阅读，下文统一写python3；应使用刚安装依赖的解释器。
Pillow与NumPy版本固定为本轮实际验证版本，避免算法/压缩器漂移。
无需登录原作者电脑、无需API密钥，也无需连接图像服务即可重建既有PNG。

5. 只验证现有资源（无需母稿）
  python3 -B scripts/verify_release.py
它检查308个ID、616张PNG、透明和颜色、7页图集与全部308区域、三个锚点、原资料一致性。
母稿存在时一并核对母稿哈希；不存在则明确记录未检查，不影响已有PNG校验。
如要强制确认已带齐母稿：
  python3 -B scripts/verify_release.py --require-mothers

6. 从保存母稿离线重建
先进行不写PNG的完整重现核对：
  python3 -B scripts/rebuild_pngs.py --verify-only
它从308张母稿在内存重做616张PNG，同时对比文件字节和解码像素哈希。
若需恢复已有发布PNG：
  python3 -B scripts/rebuild_pngs.py --write
仅当输出与冻结发布清单完全一致时才写对应PNG；不覆盖视觉验收记录。
可加 --id I001 仅处理一个ID。缺失母稿会退出并提示Release解压位置。
若在其他平台出现字节或像素差异，先按requirements版本检查；不要把差异当作自动通过。

7. 重建索引与图集（不需母稿）
  python3 -B scripts/build.py
生成manifest.json、catalog.js、atlas和联系图；不调用外部图像服务。
联系图中文字体可用ICON_FONT环境变量指向本机合法字体文件；否则依次寻找系统中文字体，
缺中文字体时降级字体仅影响QA联系图文字，不影响PNG、图集或浏览器中系统字体显示。
运行build后再执行verify_release.py，确认PNG与图集一致。
制作模块study_pixelize.py仅供脚本导入，不再依赖原来的V5平行目录。

8. 导入新母稿以修改单件
先备份原图及回执，保持data/briefs.json中的ID、名称和机制不变。
  python3 -B scripts/process_asset.py --id I001 --source path/to/new-mother.png --generation-job YOUR_JOB_ID
它重导两种尺寸、保留包内母图位置和生成job来源，并将视觉检查状态设为pending。
只记录生成job标识和源文件名；不要把账户令牌、会话ID或私人缓存路径写入公开回执。
必须重新目视确认主体、结构、完整轮廓与小尺寸辨识，并更新receipts中的实际检查结果。
之后执行build.py、verify_release.py、browser_qa.py，再package.py。
三个已认可锚点禁止被process_asset.py覆盖；恢复原图请走rebuild_pngs.py。
重新调用生成服务不保证得到相同母稿；可重复的是已保存母稿的算法转换。

9. 浏览器QA与运行时ZIP
可直接离线双击index.html，无需服务器。
可选安装浏览器测试依赖：
  python3 -m pip install playwright
  python3 -m playwright install chromium
  python3 -B scripts/browser_qa.py
已装Chrome时可加 --browser-channel chrome；也可用 --url 指向自行启动的静态服务器。
脚本默认自建仅本机的临时HTTP服务器测试下载，然后另测file://离线打开，不依赖固定端口。
测试搜索、分类、616张图片解码、下载字节、桌面/手机整数缩放和离线浏览。
随后：
  python3 -B scripts/package.py
它只在当前目录dist/生成pinball-knight-handdrawn-v6-runtime.zip，不写父目录。
运行时ZIP只含PNG、图集、简化manifest与类型，不含大尺寸母稿和制作参考。

10. 游戏接入规则与待验证项
优先以稳定ID读取runtime/manifest.json中的files["256"]或atlas.page/frame。
manifest中的资源路径相对于icons-v6资源根；runtime/manifest.json文件本身位于子目录，
不要误将pixels路径解释成runtime/pixels。
使用sRGB、Nearest/Point、Clamp，关闭mipmap，保留画布比例与透明边距。
图集坐标原点左上，未裁边未旋转，中心锚点(0.5,0.5)。
设备中实际UI缩放、触控布局、图标识别和游戏引擎纹理设置需在接入后验证。
文件技术验证、原有代理目视记录与用户/玩家体验验证是三个不同层级。
美术不能反向决定游戏机制；I035名称及sourceFlags里的未知项继续保留。

地牢搜打撤循环设计大纲 v0.1
日期：2026-10-28
状态：讨论稿。固定本轮已确认方向，其余问题保留待定；本轮不修改游戏代码。

一、游戏定位与设计目标

在现有单角色弹射战斗、装备属性、充能与天赋效果的基础上，建立“进入地牢获取战利品 → 临场组成构筑 → 击败Boss带出装备 → 局外成长与储存 → 再次挑战”的循环。

四个主要体验目标：
1. 清完一场战斗就开箱，及时获得新装备与新的搭配机会。
2. 商店把不要的战利品转成购买力，帮助玩家逐步形成自己想玩的构筑。
3. 装备需要成功带出才成为可供以后冒险使用的资产，带入的好装备也会面临丢失风险。
4. 即使死亡，本次获得的经验仍保留，角色有持续成长；成功通关还带来装备、可结算收益与新层解锁。

装备／属性／天赋资料作为内容基础继续使用；数据收录不等于每个效果都已实现并通过运行验证。新的获取方式、费用、保存边界和成长节奏另行设计，不直接继承旧原型全部规则。

二、一轮冒险的玩家流程

首次冒险：空手进入地牢。
后续冒险：可以从个人保险箱取出装备，选择本次携带的配置后进入地牢。此点已经用户确认。

营地整备
→ 选择已解锁地牢层
→ 普通战斗，清完一波敌人
→ 宝箱奖励，处理并领取战利品
→ 必定进入商店，卖出不要的装备、买入需要的装备或材料、调整构筑
→ 以50%概率进入一个锻造／附魔等特殊节点，未触发则直接继续
→ 下一场普通战斗
→ 累计完成5～6场普通战斗后挑战Boss
→ 成功结算并撤离回营地
→ 存装备、出售战利品、处理天赋成长
→ 重刷已解锁层或挑战下一层。

一次“地牢层”=5～6场普通战斗+1场Boss及中间补给环节。
“战斗序号”=本层第几场普通战斗。
不要与旧工程每进入一个房间就增加的floor字段混为一谈。

没有肉鸽分叉地图。下一节点由流程自动确定，玩家不需要每次选路线。自动推进不代替购买、出售和装备选择：战利品处理结束、商店点击离开后进入下个节点；不能用计时跳转打断整理，也不能要求必须花钱才可离开。

顺序草案按“最后一场普通战斗也经过宝箱、商店与特殊节点判定，再进入Boss”组织；Boss前是否保留特殊节点判定，后续再细化。

三、战斗与构筑

保留弹射战斗作为底盘：
- 观察敌人与场景，鼠标瞄准，发射角色，利用接触与反弹发动攻击、充能和装备效果。
- 左侧纵向战斗装备栏承载真正生效的装备；右侧背包保存当前携带但未装备的物品。
- 仅非战斗阶段允许调整装备上下顺序与跨栏装卸。
- 第一次空手进入时仍须能用角色基础能力完成第一场；基础能力和首场强度待定，不默认偷偷塞一把初始武器。
- 玩家主要在奖励、购物与加工阶段逐步组成构筑；战斗验证这一组合的表现。

后续填充：
基础能力；第一场敌人；每场战斗目标时长；各战斗难度递增；Boss要求；恢复与消耗节奏。

四、奖励、商店与特殊节点

宝箱：每场普通战斗后提供明确奖励，是频繁的获取反馈。
待定：掉落数量、品质、同名重复率、选一／全拿、背包满时如何处理。

商店：每场普通战斗的宝箱之后必定出现，支持买卖与构筑调整。
待定：货架数量、商品等级、刷新方式、买卖差价、是否回购、哪些物品可卖、金币不足时的选择。

合并、升级、附魔：方向确定，但具体服务地点与规则未定。
需要决定同名合并条件、升级成本、附魔石用途、替换／保留词条规则。

特殊节点：商店后有50%的总概率出现锻造／附魔等服务。
待定：独立抽签还是有保底；抽到的是某一种服务还是由玩家选择；是否收费；服务次数；最后一战到Boss前是否判定。
50%是“出现一个特殊节点”的概率，不默认解释成锻造50%加附魔50%。

讨论建议，尚未定案：
商店主要负责买卖装备与材料；特殊节点负责合并／升级／附魔等加工。
这能减少功能重复，但需要解决“买了材料却遇不到对应服务”的问题。若基础加工放在商店，则特殊节点应提供清楚的额外价值，不能只是同一个菜单再打开一次。

五、成功、死亡与保险箱

成功击败本层Boss：
- 本层完成，可以带着所有随身装备返回营地。
- 保留经验与等级，获得或保留对应技能点。
- 解锁下一层；已完成层仍可反复挑战。
- 玩家在营地决定哪些装备继续带着、哪些放进保险箱、哪些出售。
- 带出与入箱是两个动作；不能因为保险箱已满而静默丢弃成功带出的装备。

在本层中途死亡：
- 已装备与背包中随身携带的装备丢失，包括出发时从保险箱取出的装备和本次获得的装备。
- 本次已经获得的经验不消失，角色成长保留。
- 留在保险箱、没有带入本次冒险的物品不受影响。
- 本层战斗进度清零，需要从本层第一场重新挑战；不清除此前已经解锁的层。

待定：
死亡时金币保留、部分损失还是全部损失；材料／消耗品的损失规则；主动放弃／退出如何处理；Boss前是否存在提前撤离；成功撤离后哪些物品默认进入营地携带栏；保险箱容量与扩容方式。

六、永久成长与天赋

按用户最后确定的口径：
- 战斗获得经验，角色升级产生技能点。
- 地牢内可显示升级与技能点累积，但不能操作天赋解锁或升级。
- 回到营地后，使用技能点解锁一个新的天赋节点。
- 已解锁天赋继续升级时消耗金币。
- 天赋具有多级成长，不同天赋的等级上限与每级效果分别配置。
- 已解锁与已升级的天赋作为永久角色成长，影响后续冒险。

待定：
每级给多少技能点；节点解锁是否直接获得1级效果；前置条件与分支；各天赋上限；金币费用曲线；是否允许洗点；不同职业的成长是否共享；地牢内升级是否立即影响基础属性或恢复资源。

旧版“局内升级触发随机天赋选择”不再作为新方向的默认规则。已有天赋效果与等级参数可以复用，但获得方式和保存方式需要重做。

七、地牢层解锁与随机性

- 从已解锁层中选择出征目标。
- 通关第N层后解锁第N+1层。
- 可以继续刷已通关层，也可以挑战更高层。
- 死亡后需要重新挑战当前目标层；此前解锁进度保留。
- 节点类型的主顺序固定，房间、敌人、奖励、商店与特殊节点内容可以随机。
- 具体哪些内容随机、Boss是否固定、重入是否全部重新抽取，后续定义。

不加入路线选择地图；层选择界面只负责“这次打哪一层”。

八、先填哪些细节

优先级1：收益与损失
确认金币和死亡、提前撤离、材料与消耗品、主动放弃的处理，画出成功与死亡两条资产账本。

优先级2：奖励与消费
定义一场战斗给什么、一家商店卖什么、为什么有必要当场花钱；划清商店与特殊节点的职责。

优先级3：永久成长
定义技能点产出、天赋解锁与升级成本、上限和效果，避免玩家只刷最低风险的旧层。

优先级4：单层节奏
确定5场还是6场、战斗和菜单各占多少时间、Boss前如何准备、随机特殊节点是否保底。

优先级5：最小可玩闭环
建议先只做一个地牢层、一个角色、少量已验证装备与天赋、一套Boss和有限商店商品，跑通成功撤离与死亡后的再次出发。先验证整个循环，再扩大内容量。这是实施建议，不是已完成任务或锁定的数量方案。

九、需要用原型检查的风险

1. 菜单过密：5～6场普通战斗就有10～12次必经宝箱／商店环节，另加特殊节点；记录玩家是否连续进店立即退出，以及实际战斗／菜单用时。
2. 随机服务落空：测试全层没有特殊节点、有材料无对应服务、连续同类节点，确认基础构筑仍能完成本层。
3. 主动送死刷经验：同样时间下对比完整通关与前几波后反复死亡，后者不能在所有成长维度上都更划算。
4. 永久成长挤压局内消费：比较金币全存天赋与投资当前装备的推进效率，检查商店是否变成只卖不买。
5. 旧层刷钱压过挑战：检查最容易的已通关层是否长期成为收益最高的选择；更高层应有清楚的收益与内容价值。
6. 连续死亡后的恢复：首次空手与好装备丢光后，是否都能靠基础能力和早期奖励重新形成构筑，避免只剩无效刷经验。

上述是待测试的问题，不代表已证实好玩或已出现失败。

十、与旧工程及旧交接提示词的关系

已有基础可以复用：弹射与战斗、物品效果、部分合并／制造／附魔操作、库存与持久仓库结构。
需要重建：固定节点推进、成功撤离、死亡保留经验、持久角色成长、局外技能点／金币天赋操作、逐层解锁。

旧工程当前返回营地会触发新轮回并重置成长，不符合本大纲。独立战斗HTML也只是一场战斗切片，不能当作新循环已经完成。

上一版HUD Prompt中“保留旧成长规则”和“局内随机天赋选择”等条款需要在未来施工交接时同步替换。左右布局、物品数据真实性和输入保护仍可沿用。本次只形成设计大纲，不改旧HTML、不启动新玩法实现。
